# Research findings (2026-10-17)

These facts were checked against primary sources by two research agents. Four were also tested by running code (see `spikes/` and `../design/sql/03_rls_tests.sql`). The design doc's "To verify" table has the one-line version; this file keeps the details adapters will need.

## LangGraph (tested on 1.2.15)

- **Fan-out:** `Command(goto=[...])` accepts a list of node names or `Send` objects (present since at least 0.2.57). Tested: both subagents ran in one superstep, and the orchestrator ran once after them. `Command` adds dynamic edges only; static `add_edge` edges from the same node still run. [types.py](https://raw.githubusercontent.com/langchain-ai/langgraph/main/libs/langgraph/langgraph/types.py)
- **Pydantic state:** supported, with `Annotated[list[X], reducer]` fields. Tested: the `merge_by` reducer replaces entries on a redo. Validation runs only on input to the first node, and graph output is a dict (its list items stay model instances), so rebuild with `AgentState(**out)`. It is slower than TypedDict. [use-graph-api](https://docs.langchain.com/oss/python/langgraph/use-graph-api)
- **Durability:** `durability="sync" | "async" | "exit"`, default `"async"`, passed per call to `invoke`/`stream` (not to `compile`). It replaced `checkpoint_during` in 0.6.0. [release](https://github.com/langchain-ai/langgraph/releases/tag/0.6.0)
- **PostgresSaver:**
  - Tables: `checkpoint_migrations`, `checkpoints`, `checkpoint_blobs`, `checkpoint_writes`.
  - `setup()` must be called explicitly.
  - Own connections need `autocommit=True, row_factory=dict_row`.
  - `from_conn_string` uses `prepare_threshold=0`, which breaks PgBouncer transaction mode before PgBouncer 1.22. Use `prepare_threshold=None` there.
  - Keyed only by `thread_id`, `checkpoint_ns` and `checkpoint_id`; there is no tenant scoping.

  [README](https://github.com/langchain-ai/langgraph/blob/main/libs/checkpoint-postgres/README.md), [base.py](https://raw.githubusercontent.com/langchain-ai/langgraph/main/libs/checkpoint-postgres/langgraph/checkpoint/postgres/base.py), [psycopg prepare](https://www.psycopg.org/psycopg3/docs/advanced/prepare.html)

## Postgres RLS and ACID (tested on Postgres 16)

- Superusers and `BYPASSRLS` roles always bypass RLS. Table owners bypass it unless `FORCE ROW LEVEL SECURITY` is set. With no policy, access is denied by default. [ddl-rowsecurity](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)
- `UPDATE ... RETURNING` and `ON CONFLICT DO UPDATE` also need a passing SELECT policy. Referential integrity checks bypass RLS, and `TRUNCATE` ignores it.
- `set_config(name, value, true)` lasts until the end of the transaction, committed or not. Tested: afterwards, `current_setting(name, true)` returns `''` (not NULL) on that connection, and NULL if it was never set, so wrap it in `nullif(..., '')`. Session `SET` is unsupported under PgBouncer transaction pooling. [functions-admin](https://www.postgresql.org/docs/current/functions-admin.html), [PgBouncer](https://www.pgbouncer.org/features.html)
- `SECURITY DEFINER` functions: pin `search_path` with `pg_temp` last, and revoke PUBLIC `EXECUTE`. [CREATE FUNCTION](https://www.postgresql.org/docs/current/sql-createfunction.html)
- Cloud SQL supports RLS and offers no true superuser. Whether `cloudsqlsuperuser` has `rolbypassrls` is **undocumented**; check `pg_roles` on the instance. [Cloud SQL users](https://docs.cloud.google.com/sql/docs/postgres/users)
- Under READ COMMITTED, a compare-and-set `UPDATE ... WHERE status = $expected` re-checks the `WHERE` after a concurrent update, so the loser gets 0 rows. `ON CONFLICT` arbiters must be NOT DEFERRABLE. Use `SKIP LOCKED` for queue-like claiming. [transaction-iso](https://www.postgresql.org/docs/current/transaction-iso.html), [INSERT](https://www.postgresql.org/docs/current/sql-insert.html)

## GCP limits

- **Cloud Tasks HTTP deadline:** 15 s to 30 min (default 10 min). [tasks](https://docs.cloud.google.com/tasks/docs/reference/rest/v2/projects.locations.queues.tasks)
- **Cloud Run request timeout:** up to 60 min (default 5 min). [request-timeout](https://docs.cloud.google.com/run/docs/configuring/request-timeout)
- **Cloud Tasks task ids:** a deleted task's id stays reserved for up to 24 hours (9 days for queue.yaml queues). Sequential ids or prefixes raise latency and error rates, so hash them. [tasks.create](https://docs.cloud.google.com/tasks/docs/reference/rest/v2/projects.locations.queues.tasks/create)

## Providers

- **ElevenLabs TTS:**
  - `POST /v1/text-to-speech/{voice_id}/with-timestamps` returns `audio_base64` plus `alignment` and `normalized_alignment`, each with `characters`, `character_start_times_seconds` and `character_end_times_seconds`. Timing is per character only, so group characters into words.
  - A streaming variant exists: `/stream/with-timestamps`.
  - Pronunciation dictionaries are passed via `pronunciation_dictionary_locators: [{id, version_id}]`.
  - Models: `eleven_v4`, `eleven_v4_turbo`, `eleven_v3`, `eleven_multilingual_v2` (the default; recommended for narration), `eleven_flash_v2_5`. Turbo v2/v2.5 are deprecated.
  - Not yet checked: timestamp and dictionary support per model.

  [with-timestamps](https://elevenlabs.io/docs/api-reference/text-to-speech/convert-with-timestamps), [models](https://elevenlabs.io/docs/models)
- **Gemma 4:**
  - Sizes E2B, E4B, 12B, 26B A4B and 31B, with 128K context (small) or 256K (medium).
  - Text and images can be mixed freely in one prompt. Video is read as frames, up to 60 s at 1 fps. Audio input works on E2B/E4B/12B only, ≤ 30 s.
  - Apache 2.0, available in Vertex AI Model Garden.

  [model card](https://ai.google.dev/gemma/docs/core/model_card_4), [GCP blog](https://cloud.google.com/blog/products/ai-machine-learning/gemma-4-available-on-google-cloud)

## Browser capture (Chrome)

- **Tab audio** is shared by default. **Window and whole-screen audio** need "Also share system audio": Chrome 141 added `windowAudio: exclude | system | window`, and `systemAudio` defaults to `include`. On macOS Sequoia, the OS screen and system-audio permission is required. [Chrome 141](https://developer.chrome.com/release-notes/141), [Meet help](https://support.google.com/meet/answer/9308856)
- The stream may have **no audio track** even with `audio: true`, so the recorder must check for one and warn. [MDN](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia)
- Capture options:
  - `preferCurrentTab` adds a "This Tab" option.
  - `selfBrowserSurface` defaults to `exclude`.
  - Set `surfaceSwitching` explicitly, because its default may change.

  [screen-sharing controls](https://developer.chrome.com/docs/web-platform/screen-sharing-controls)
- `MediaRecorder` can write MP4 since Chrome 126. [Chrome 126](https://developer.chrome.com/release-notes/126)
- **Chunked upload while recording works:**
  - `timeslice` chunks are not playable alone, but their concatenation is. [spec](https://w3c.github.io/mediacapture-record/)
  - Append the chunks to one GCS resumable session in 256 KiB multiples, with total size `*` until the end.
  - The session URI lasts a week and is a bearer credential. [resumable uploads](https://docs.cloud.google.com/storage/docs/performing-resumable-uploads)
- **Still unverified:** which operating systems support whole-screen system audio; mixing the mic into the display stream; Chrome's default MediaRecorder codecs. Needs a hands-on spike.
